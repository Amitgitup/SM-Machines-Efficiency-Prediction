# 🏭 Smart Manufacturing Machine Efficiency Prediction

Welcome to the **Smart Manufacturing Machine Efficiency Prediction** project! This project focuses on building, training, and tracking a machine learning model to predict and analyze the efficiency of machinery in an industrial setting. 

We utilize a robust data processing pipeline and optimal hyperparameter tuning via `RandomizedSearchCV` on a Logistic Regression model to find the best performing model. The entire pipeline is explicitly integrated with **MLflow** for robust experimentation and metric tracking.

## 📁 Project Structure

```text
.
├── artifacts/              # Contains the raw data, processed datasets, and serialized models
├── logs/                   # Log files generated by our custom logger configuration
├── pipeline/               # Defines the execution pipelines 
│   └── training_pipeline.py# Script to run data processing and model training sequentially
├── src/                    # Source code directory containing all module logic
│   ├── data_processing.py  # Cleans, splits, and processes the raw data

│   ├── model_training.py   # Handles model initialization, tuning, evaluation, and logging

│   └── custom_exception.py # Custom exception handling tools
├── mlflow.db               # SQLite database acting as our MLflow tracking backend store
├── mlruns/                 # Legacy/default file-based storage for MLflow experiments
├── requirements.txt        # Contains all necessary Python dependencies
└── README.md               # You're reading it!
```

## 🚀 How to Run the Pipeline

Make sure you have your virtual environment activated and all dependencies installed from `requirements.txt`.

To execute the entire data processing and model training workflow, run:
```bash
python pipeline/training_pipeline.py
```
*(Or, you can individually run `python src/model_training.py`)*

This will automatically process your dataset, train the logistic regression model, evaluate it, and seamlessly log all models, parameters, and metrics straight into MLflow!

## 📊 MLflow Integration & How to Use It

Our model training step uses `mlflow` to automatically log and version control all of our model experiments.

To view your logged metrics, parameters, and artifacts visually, open up your terminal and launch the MLflow UI:
```bash
mlflow ui
```
You can then open a web browser and navigate to the local host address provided in the terminal (usually `http://127.0.0.1:5000`) to interact with your dashboard.

### ⚠️ IMPORTANT: The "No Runs Logged" MLflow Issue & Troubleshooting

When using MLflow, you might encounter a frustrating issue where you successfully run your training pipeline without an error and open the `mlflow ui`, but the dashboard is entirely blank and says **"No runs logged"**.

**Why does this happen?**
By default, if no tracking URI is provided in the code, MLflow saves your experiments into a local file directory called `./mlruns`. However, if an `mlflow.db` database is present in your working space, running the simple command `mlflow ui` might automatically hook up to the empty `mlflow.db` data store instead of the `mlruns` directory. Because your background script saved its runs to a folder, but your visual UI is querying the empty database, you won't see anything.

**How our project solves this:**
To permanently fix this discrepancy, we explicitly configured the backend tracking URI inside the `src/model_training.py` script before setting up the experiment run:
```python
mlflow.set_tracking_uri("sqlite:///mlflow.db")
mlflow.set_experiment("SM_Machine_Efficiency_Prediction")
```
Now, all backend Python code pushes logs directly into the `mlflow.db` database. Since `mlflow ui` also points to this exact database, the synchronization is perfect! Additionally, using a database back-end unlocks advanced MLflow capabilities like the **MLflow Model Registry**, which is not supported by standard file paths.

**What if I want to see my old, legacy runs?**
If you ever want to review legacy runs that were strictly logged to the folder system before the sqlite database connection was established, simply force the UI to look at the folder using this command:
```bash
mlflow ui --backend-store-uri file:./mlruns
```
